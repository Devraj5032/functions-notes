Introduction to Methods
⌄
What is a Method?
A method is a named block of code that performs a specific task. It is defined once and can be called (invoked) multiple times. In Java, all functions must be inside a class — so they are called methods.
Think of a method like a recipe — written once, cooked (called) many times.
Why use Methods?
Reusability Write once, use many times

Modularity Break big problems into parts

Readability Easier to understand

Debugging Test individual pieces
Method vs Function
In Java, there are no standalone functions. Every function must be inside a class, so we call them methods.

In BlueJ, you can see and call all public methods of an object by right-clicking it on the workbench.

Structure of a Method
⌄
General Syntax
// Method syntax accessModifier returnType methodName(parameterList) { // body of the method return value; // only if returnType ≠ void }
Access Modifiers
public Accessible everywhere
private Only within the class
protected Class & subclasses
(default) Same package only
Parts of Method Header
returnType — type of value returned
methodName — camelCase name
parameterList — inputs (can be empty)
body — statements inside { }
Complete Example
public class Calculator { // Method that returns a value public int add(int a, int b) { int sum = a + b; return sum; } // Method with no return value public void greet() { System.out.println("Hello, ICSE Student!"); } }
Calling a Method (in BlueJ)
Calculator obj = new Calculator(); // Step 1: create object int result = obj.add(5, 3); // Step 2: call method obj.greet(); // void method call System.out.println(result); // prints 8
In BlueJ, right-click any object on the workbench to call its methods interactively without writing extra code!

Types of Methods
⌄
Type 1 Void Methods
Do NOT return any value. Use void as return type.
public void display() { System.out.println("Hello"); }
Type 2 Non-Void Methods
Return a value using return. Return type must match.
public int square(int n) { return n * n; }
Type 3 Parameterized
Accept input values to work with.
public void printName(String name) { System.out.println(name); }
Type 4 Non-Parameterized
Take no input. Use class-level data.
public void showPI() { System.out.println(3.14159); }

Parameters & Arguments
⌄
Formal Parameters
Variables declared in the method definition — act as placeholders.
// a and b are formal parameters int add(int a, int b) { ... }
Actual Arguments
Real values passed when calling the method.
// 10 and 20 are actual arguments obj.add(10, 20);
Call by Value vs Call by Reference
Call by ValueCall by Reference
Copy of value is passedReference (address) is passed
Original variable unchangedOriginal may change
Used for primitive types (int, char, double…)Used for objects and arrays
// Call by Value: original is unchanged void change(int x) { x = 100; // only local copy changes } int a = 5; change(a); System.out.println(a); // still prints 5
In Java, primitive types are always passed by value. Objects are passed by reference — changes inside the method affect the original object.

Return Types
⌄
The return Statement
Used to send a value back to the caller. Execution of the method stops at return.
public String grade(int marks) { if (marks >= 90) return "A+"; else if (marks >= 75) return "A"; else return "B"; } // Calling: String g = obj.grade(88); → g = "A"
Common Return Types
Return TypeUseExample
voidReturns nothingdisplay()

doubleReturns decimal numberarea(r)

charReturns a characterfirstChar(s)
The return type in the method header and the value being returned MUST match. A mismatch causes a compile-time error in Java.

Method Overloading
⌄
What is Method Overloading?
Defining multiple methods with the same name but different parameter lists. Java selects the correct method at compile time based on arguments passed. This is called compile-time polymorphism.
✓ Valid Overloading
Different number of parameters
Different types of parameters
Different order of parameter types
✗ NOT Overloading
Only return type is different
Only parameter names differ
Only access modifier differs
Overloading Example
public class MathOps { // Version 1: two integers public int multiply(int a, int b) { return a * b; } // Version 2: three integers public int multiply(int a, int b, int c) { return a * b * c; } // Version 3: two doubles public double multiply(double a, double b) { return a * b; } } // Java picks the right version automatically! // obj.multiply(2,3) → uses Version 1 // obj.multiply(2,3,4) → uses Version 2 // obj.multiply(2.5, 3.0) → uses Version 3
Java automatically picks the correct method based on the number and type of arguments — this is called method dispatch.

Scope of Variables
⌄
Local Variables
Declared inside a method. Exist only while the method runs. Must be initialized before use. Not accessible outside the method.
void show() { int x = 10; // local System.out.println(x); } // x not accessible here
Instance Variables
Declared inside class, outside all methods. Accessible to all methods. Default values assigned (0 for int, null for String, etc.).
class Student { int age; // instance var void show() { System.out.println(age); } }
Variable Shadowing & the this keyword
When a local variable has the same name as an instance variable, the local variable takes priority (called shadowing). Use this.variableName to access the instance variable.
class Box { int length; // instance variable void setLength(int length) { // 'length' here refers to parameter (local) this.length = length; // 'this.length' = instance variable } }
If a local variable name shadows an instance variable and you forget this., the instance variable does not get updated — a very common bug!
⑧
Recursion
⌄
What is Recursion?
A method that calls itself to solve a smaller version of the same problem. Every recursive method must have a base case — a condition that stops the recursion.
Factorial — n!
public int fact(int n) { if (n <= 1) return 1; // base return n * fact(n-1); } // fact(4) = 4×3×2×1 = 24
Fibonacci Series
public int fib(int n) { if (n <= 1) return n; // base return fib(n-1) + fib(n-2); } // fib(5) → 0,1,1,2,3,5
How Recursion works — Factorial(4)
fact(4) → 4 × fact(3) → 3 × fact(2) → 2 × fact(1) → 1 (base case reached!) ↑ Now unwinds: 2×1=2 → 3×2=6 → 4×6 = 24
Always define a base case! Without it, the method calls itself forever and causes a StackOverflowError at runtime.

Method calls itselfUses for/while loop
Uses call stack memoryUses less memory
Elegant for tree/math problemsFaster in practice

B int add(int x, int y)
C int add(int a, int b, int c)
D private int add(int a, int b)
✓ Correct! Adding a third parameter changes the parameter list — making it a valid overload.
✗ Incorrect. Overloading requires different parameter lists. Only changing return type or access modifier is NOT valid overloading.
3What is a local variable?
A A variable declared inside a method
B A variable declared inside a class but outside all methods
C A variable declared using the static keyword
D A variable accessible throughout the program
✓ Correct! A local variable is declared inside a method and only exists during that method's execution.
✗ Incorrect. A local variable is declared inside a method, not at class level. Instance variables are declared inside the class but outside methods.
4What happens if a recursive method has no base case?
A It returns 0
B It returns null
C It gives a compile-time error
D It causes a StackOverflowError at runtime
✓ Correct! Without a base case, the method keeps calling itself indefinitely, exhausting the call stack and causing a StackOverflowError.
✗ Incorrect. The code compiles fine but crashes at runtime with a StackOverflowError because the method calls itself forever.
5What keyword is used to access an instance variable when it is shadowed by a local variable?
A super
B this
C self
D instance
✓ Correct! this.variableName refers to the instance variable of the current object, distinguishing it from a local variable with the same name.
✗ Incorrect. The keyword this refers to the current object and is used to access its instance variables when they are shadowed.
6In call by value, what is passed to the method?
A The original variable itself
B The memory address of the variable
C A copy of the value
D A reference to the object
✓ Correct! In call by value, only a copy of the value is passed. The original variable remains unchanged after the method call.
✗ Incorrect. In call by value, a copy of the value is passed. Changes inside the method do not affect the original variable.
